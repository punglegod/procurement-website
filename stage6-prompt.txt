先读取本目录的 AGENTS.md 并严格遵守。第一至五阶段已完成（版本以 git log 为准）。本阶段只做审计与报告：不改任何业务代码，不提交 git。

任务：对整个项目做一次安全审计 + bug 排查，重点如下。
1. 认证与会话：密码哈希、会话令牌的生成与存储、Cookie 属性、登录节流、改密/禁用/删除后旧会话失效、管理员播种逻辑、注册提权防护。
2. 越权（本项目核心）：逐个接口核对账号隔离——提醒规则、推送设置、推送日志、立即检查、回放；用 B 账号拿 A 的资源 id 逐个试（查看/修改/删除）；普通账号访问全局接口（数据源、抓取、Telegram 状态、用户管理、注册开关）的拦截是否完整。
3. 注入与输入：SQL 是否全参数化；前端 XSS（转义与 v-html 使用）；SSRF（各行情源 URL 拼接与重定向）；路径穿越；请求体大小与类型校验。
4. 密钥与配置：代码、日志、示例文件、git 全部历史里有没有混入真实密钥、密码、token；.env 读取与默认值是否安全；报错信息是否泄露堆栈或内部路径给前端。
5. 依赖：后端跑 pip-audit、前端跑 npm audit（跑不了就写明原因，并人工核对 requirements.txt 与 package.json 里有无已知严重漏洞的版本）。
6. 业务逻辑 bug：抓取调度的时区与重复执行、提醒去重的跨日/并发/重启边界、涨跌幅与口径计算、SQLite 并发与事务、空数据与分页、前端错误处理与状态残留。
7. 部署面：Dockerfile 与 docker-compose.yml 的运行用户、端口绑定、卷权限、健康检查；应用进程权限。

方法要求：不要只读代码下结论。能复现的必须写复现脚本或对抗测试实际运行，并把输出贴进报告（临时测试文件放 backend/tests 或 scripts 下，在报告里列明）。全量跑一遍现有测试确认基线是否全绿。

产出：在项目根目录写 AUDIT_REPORT.md。发现按 严重 / 高 / 中 / 低 分级，每条含：位置（文件与行号）、证据（复现输出或代码片段）、影响、修复建议。没有发现问题的类别也要写「已查，未发现」。最后给一份修复优先级清单。写完停下等确认，不要动手修复任何发现。
